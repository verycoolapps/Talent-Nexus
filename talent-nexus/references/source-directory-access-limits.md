# Source Directory and Source-Access Limits

Use these categories to plan professional-source discovery. They are source categories, not guarantees that any named service is reachable, searchable, or automation-permitting.

## Non-exhaustive professional source categories and examples

Examples below illustrate source types, not endorsements or verified capabilities. No example implies access, searchability, permission to automate, or permission to reuse content.

- **Professional networks:** LinkedIn public professional profiles and public association/member directories.
- **Code/technical communities:** GitHub and GitLab public projects; Kaggle notebooks/competitions; Stack Overflow public professional contributions.
- **Academic sources:** ORCID public records, Google Scholar profiles, institutional pages, Crossref, arXiv, and university repositories.
- **Portfolios/creative work:** Behance, Dribbble, ArtStation, Vimeo, personal portfolio sites, and public case studies.
- **Knowledge sharing:** Medium and Dev.to articles; public blogs, newsletters, podcasts, and recorded talks.
- **Associations/events/company sources:** public association or credential directories, conference/event pages, company/team pages, press releases, and public job boards.
- **Professional social content:** relevant public professional content on X, Threads, YouTube, Instagram, or TikTok only when work-related and appropriate to the purpose.

Examples are non-exhaustive. A named platform may be unavailable, require account access, restrict automated access, or prohibit reuse. Check source terms, tool capabilities, applicable law, and organizational policy before access or automation; never bypass access controls.

## Access protocol

1. Confirm an actual host tool or user-provided source is available. State its name and limits only when observed. If none exists, produce a query plan for a human to run; do not claim live access.
2. Use only content that is publicly accessible without login circumvention, credentials, private-account access, or unauthorized scraping. Respect terms, robots/rate restrictions, API conditions, and applicable law; do not assume automation is allowed.
3. Avoid broad collection. Search narrowly for role-relevant evidence and retain only the minimum needed for the stated professional purpose.
4. Capture the source title, exact URL, and access date only when actually viewed. If the source is unavailable or the date is unknown, say so.
5. Public availability is not proof of accuracy, identity, consent to contact, or permission to republish. Attribute and qualify each claim.

## Source record

For each source: category; source title; URL (or explicit “not provided”); accessed date or “not accessed”; observed access method/tool or “query plan only”; professional relevance; limitations; and any use/access restriction noticed. Never invent a source, URL, access, or result.
